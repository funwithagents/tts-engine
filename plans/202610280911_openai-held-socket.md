# OpenAI Realtime: one socket held for the module's lifetime

**Status:** Done

Implements the settled behavior in `specs/modules/openai.md` ("One socket, held for the module's lifetime", "Threading and cancellation", "Events read", "Validation", "Error handling", "Lifetime"). The `openai` module opens its Realtime socket in `__init__` and keeps it across utterances — reconnecting when it dies, rotating it before the 60-minute session cap, filtering the events of earlier responses, attributing `error` events by `event_id` — so no `say()` pays the 0.5–0.9 s WebSocket handshake. It deliberately leaves out overlapping the next sentence's response (spec open question 1) and any config knob: the held socket is unconditional, like the Cartesia context rotation and the HTTP connection pools of the other providers.

Why now: the TTFA benchmark (`analysis/ttfa-benchmark/`, run 20261027-145315) measured a 1.24 s mean time to first audio for this module, the slowest of every backend; `analysis/ttfa-benchmark/openai_realtime_breakdown.py` showed 0.5–0.9 s of it is the handshake and the rest the model's own 0.5–0.8 s floor, which no setting (`reasoning.effort` included) lowers.

## Scope

- `src/tts_engine/modules/openai/module.py` — the socket moves from `_synthesize` to the module: `_Socket` gains its open time, a `dead` flag set by the reader and by a failed send, and a `closed` guard; `_open` becomes the setup sequence (handshake through `open_cancellable`, reader started, `session.update` with an `event_id`, wait for `session.updated` or `error`) used by `__init__` and by the worker's reconnect; `_synthesize` runs the dead-socket and rotation checks, then the responses, and never closes the socket on the way out; `_respond` tags `response.create`/`response.cancel` with `event_id`s, skips events of other responses, attributes `error` events; `_cancel` waits for `response.created` when it has no `response_id` yet; `close()` closes the socket off the calling thread, then the client.
- `tests/modules/test_openai.py` — the fake connection answers `session.update` with `session.updated`, records `event_id`s, counts `connect` calls, can script events of a foreign `response_id` and `error` events with a chosen `event_id`; new tests for construction, reuse, reconnect, rotation, stale events, cancel-before-created, `close()`.
- `specs/modules/openai.md` — status `Updated` → `Implemented` once the plan is done; no text change expected (the plan implements it as written). `specs/_index.md` — mirror the status.
- No change to `examples/config.openai.json`, `tests-e2e/`, `pyproject.toml` or the registry: the config fields, the live conformance scenarios and the dependency are unchanged. The live row exercises the held socket for free (every scenario constructs a module and speaks at least once; the cancel scenario then speaks again on the same socket).

## Steps

1. **`_Socket` as a long-lived object.** Add `opened: float` (`time.monotonic()` at setup), `dead: threading.Event` (set by `_read` when `recv()` raises or returns, and by any `send` that raises), and a `closed` flag so `_close` runs once. Keep the bounded inbox (64 events). The reader thread is started in setup and lives with the socket; it stops putting once `dead` is set or the socket closed (today's "worker has left" condition becomes "socket closed").
2. **Setup sequence `_open(stop) -> _Socket`.** Handshake through `open_cancellable` as today (the constructor passes a fresh, never-set `threading.Event()` as `stop`); start the reader; send `session.update(session=self._session, event_id=<new id>)`; take events from the inbox (50 ms poll, `timeout` bound) until `session.updated` (return the socket) or `error` (close the socket off-thread, raise `_SetupRejected(code, message)`), a reader exception or the timeout (close off-thread, raise `TTSError`). Event ids: a module-level counter formatted as `tts-<n>`; keep the ids of the utterance's own client events in a per-utterance `set[str]` plus the setup id, for attribution.
3. **Construction connects.** At the end of `__init__`, after the client is built: `self._socket = self._open(threading.Event())`, mapping `_SetupRejected` to `ConfigError(f"OpenAI module: {code}: {message}")` (chained) and leaving `TTSError` as is. A failed construction leaves no socket and closes the client. `close()` on a module whose `_socket` is `None` or dead closes only the client.
4. **Per-utterance checks in `_synthesize`.** Before the first non-blank text (a blank utterance returns before any check): if `self._socket is None` or `dead` is set → close the old one off-thread, `self._socket = self._open(stop)` (a `_SetupRejected` here is a `TTSError`); else if `time.monotonic() - opened > _ROTATE_AFTER` (55 × 60 s, a module constant next to `_INBOX_EVENTS`, with the comment on the 60-minute cap) → close off-thread, reopen the same way. `_open` returning `None` (cancelled during the handshake) ends the utterance as today. The utterance then runs its responses over `self._socket`; on the way out it closes nothing. A transport exception during `response.create` sets `dead` before raising `TTSError`.
5. **Response-scoped event handling in `_respond`.** Send `response.create(response=..., event_id=<new id>)`, remember the id. For each inbox event: `response.created` → if `response_id` is still unknown, take `event.response.id` (the first `response.created` seen after this utterance's `response.create` is its own, because responses on the socket are serialized and the previous utterance's `response.created` was consumed by that utterance — document this in a comment); otherwise skip it at DEBUG if it names another response. `response.output_audio.delta` with another `response_id`, and `response.done` whose `response.id` is another response → skip at DEBUG. `error` → `event.error.event_id in own_ids or event.error.event_id is None` → `TTSError` as today; else DEBUG and continue. The reader's exception → set `dead`, `TTSError`. `response.done` of the current response → as today. The `timeout` between events stays.
6. **Cancel without closing.** On `stop`: if `response_id` is known, `response.cancel(response_id=..., event_id=<new id>)` best effort and return `False` (the socket stays). If unknown, keep taking events (same loop, `timeout` bound) until the current response's `response.created` arrives, then cancel; on timeout or a dead socket, close the socket off-thread and set `self._socket = None` so the next utterance reconnects. The id set of the utterance keeps the cancel's id: an `error` for it arriving during a later utterance is a foreign id there and is ignored by step 5.
7. **`close()`.** Close the held socket off the calling thread (reuse the daemon-thread `_close`), set `self._socket = None`, then `self._client.close()`.
8. **Tests.** Extend the fake: `_Connection.session.update` records `event_id` and enqueues `session.updated` unless the script says otherwise (`reject_setup=<code>` enqueues an `error` whose `error.event_id` is the update's id; `silent_setup=True` enqueues nothing); `response.create`/`cancel` record `event_id`; `_Server.connects` counts `connect` calls; helpers `_created(response_id)`, `_delta(pcm, response_id)`, `_done(status, response_id)`, `_error(code, event_id)`. Tests, one behaviour each: construction connects once and sends `session.update` before any `say`; `reject_setup` is `ConfigError` naming the code with no socket left (`connection.closed` true) and the client closed; a silent setup and a handshake exception are `TTSError`; two `_say` calls make one `connect` and two `response.create`; events of a foreign `response_id` and an `error` with a foreign `event_id` leave the utterance's audio intact; an `error` with the utterance's `event_id`, one with `event_id=None`, a non-`completed` status and a silent server raise `TTSError` with the socket still open; a reader exception raises `TTSError`, marks the socket dead, and the next `_say` reconnects (`connects == 2`) while a reconnect failure is `TTSError` with `connects == 2` and the next call tries again; a rotation under `monkeypatch.setattr(module_under_test.time, "monotonic", ...)` with `opened` 56 minutes in the past reconnects before the utterance's `response.create` and not inside it; cancel (`stop` set mid-audio) sends `response.cancel` with the id and `event_id` and leaves the socket open; a `stop` set before `response.created` arrives still produces a `response.cancel` once it does; `close()` closes the socket and the client, and only the client after a reader failure. Update the existing tests that asserted a socket closed after an utterance or an error (`test_server_failures_are_tts_error_and_close`, `test_callback_error_propagates_unchanged_and_closes`, `test_blank_text_opens_no_socket` → "sends nothing") to the held-socket behaviour.
