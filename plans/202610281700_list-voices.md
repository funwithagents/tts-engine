# Voice listing

**Status:** Done

Implements `specs/tts-module-interface.md` ("Voice listing") and the "Voice listing" section of every `specs/modules/<backend>.md`: a `TTSModule.list_voices(config)` classmethod returning `VoiceInfo` entries, implemented by every module that has a catalog to read, and a `VoiceListingUnsupported` error pointing to the documentation for the three that have none (gemini, openai, openai-compatible). No filtering, no CLI and no caching: the voice-audition tool, a later plan, is the first consumer.

## Scope

- `src/tts_engine/modules/base.py` — `Gender`, `VoiceInfo`, `VoiceListingUnsupported`, `normalize_gender`, the default `TTSModule.list_voices` (raises `VoiceListingUnsupported`)
- `src/tts_engine/modules/__init__.py` — `list_voices(module_config)` through the registry
- `src/tts_engine/__init__.py` — re-export `list_voices`, `VoiceInfo`, `VoiceListingUnsupported`
- `src/tts_engine/modules/<backend>/module.py`, all fifteen — the `list_voices` classmethod
- `tests/modules/test_tts_module_interface.py` — `normalize_gender`, the registry-level `list_voices`, every registered module overrides the default
- `tests/modules/test_<backend>.py` — each module's listing against its faked SDK, catalog or file
- `tests-e2e/test_voices.py` — live listing for every row of `support.MODULES`: a non-empty list whose entries' `config` builds a module, or `VoiceListingUnsupported`
- `specs/tts-module-interface.md`, `specs/modules/*.md`, `specs/_index.md` — the contract and one "Voice listing" section per module; statuses
- `plans/_index.md` — this plan's row

## Steps

1. **Base types.** In `base.py`: `Gender = Literal["male", "female", "neutral"]`; frozen `VoiceInfo` (`id`, `name`, `config`, `languages`, `gender`, `age`, `description`, `tags`); `VoiceListingUnsupported(Exception)`; `normalize_gender(value) -> Gender | None` mapping the backends' words (`male`, `masculine`, `m`, `man`; `female`, `feminine`, `f`, `woman`; `neutral`, `gender_neutral`, `non-binary`, `nonbinary`, `androgynous`), case-insensitively, anything else to `None`. `TTSModule.list_voices` raises `VoiceListingUnsupported(f"The '{type}' module cannot list its voices")`, so every module overrides it.
2. **Registry function.** `modules.list_voices(module_config)`: unknown type → `ConfigError`, else `REGISTRY[type].list_voices(module_config)`; re-exported from `tts_engine`.
3. **Hosted providers with an endpoint**, each importing its SDK lazily (missing extra → the constructor's `ConfigError`), resolving the key with `resolve_api_key`, and turning an SDK or network failure into `TTSError("<Label>: voice listing failed: …")`:
   - `elevenlabs` — `ElevenLabs(api_key).voices.get_all()`; `labels` give gender, age, accent and use case (tags), description; `voice_id`.
   - `cartesia` — `Cartesia(api_key).voices.list(limit=100)` iterated across pages; `language`, `gender`, `description`; `voice_id`.
   - `deepgram` — `DeepgramClient(api_key).manage.v1.models.list().tts`; gender from the `masculine` / `feminine` metadata tag, the other tags, accent and use cases as tags, age; `model` = `canonical_name`.
   - `gradium` — `GradiumClient(api_key, base_url).voice_get(include_catalog=True)` on a private event loop in a helper thread (so the call also works from a thread that runs a loop); `gender`, `age`, `language` / `locale`, description, tag values other than gender and age; `voice_id` = `uid`.
   - `mistral` — `Mistral(api_key).audio.voices.list(limit=100, offset=…)` until a short page; `gender`, `age` (years), `languages`, `tags`; `voice_id`.
4. **Hosted providers without one** — `gemini`, `openai`, `openai-compatible` raise `VoiceListingUnsupported` naming the documentation page (and, for `openai-compatible`, that another server documents its own voices).
5. **Local models:**
   - `phonon` — `ptts.catalog_voices()`; `voice` = the catalog name, language and description.
   - `pocket` — the preset names of pocket-tts's built-in table (read through `getattr`, as it is private; absent → `VoiceListingUnsupported` with the pocket-tts README); `voice` = the name, the source recording as description.
   - `piper` — `voices.json` at the pinned commit through `hf_hub_download`; one entry per voice, or per speaker of a multi-speaker voice (`speaker` added to `config`); language code, quality and dataset as tags.
   - `kokoro` — the keys of the voices file (the configured `voices`, else the pinned default) loaded with `numpy.load`; language from the first letter (the module's table), gender from the second.
   - `qwen3` — a VoiceDesign model raises `VoiceListingUnsupported` (its voice is the `instruct` text); otherwise the configured model and quant are loaded, `speaker_names()` read and the model closed.
6. **Fixtures** — `tone` and `audiofile` return `[]`.
7. **Specs** — a "Voice listing" section in each module spec; `tts-module-interface.md` and every module spec back to `Implemented` once the code matches.
8. **Live tier** — `tests-e2e/test_voices.py` over `support.MODULES`, skipping like the other live tests.
