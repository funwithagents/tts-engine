# Module `kind`: hosted, local or fixture

**Status:** Done

Implements [specs/tts-module-interface.md](../specs/tts-module-interface.md) ("`TTSModule` ABC", "Module kinds") and [specs/benchmark.md](../specs/benchmark.md) ("Two summaries"). Every module declares where its synthesis runs as a class attribute, `kind`, one of `hosted`, `local`, `fixture`; the latency benchmark records it with every measurement and splits its summary into a Local and a Hosted table. It deliberately leaves out exposing `kind` through the engine or the MCP server (nothing asks for it yet) and any behaviour keyed on it inside the library.

## Scope

- `src/tts_engine/modules/base.py` — `ModuleKind` literal and the `kind: ClassVar[ModuleKind]` declaration on `TTSModule`, no default.
- `src/tts_engine/modules/<backend>/module.py` (15 files) — one `kind = "..."` line per class, per the spec's table.
- `tests/modules/test_tts_module_interface.py` — the expected mapping, asserted against the registry.
- `benchmarks/latency/bench.py` — every record carries `kind` (from the registry, written by the worker and by the parent's skip/abort/done records); `results.csv` and `summary.csv` gain a `kind` column; `summary.md` has a Local and a Hosted table, fixtures in `results.csv` only; the hard-coded fixture set goes.
- `tests/test_benchmark.py` — records carry `kind`; the split and the column are asserted.
- `benchmarks/latency/results/20261027-1453_mac-m5-pro/` — the packed records and the local runs migrated once (`kind` added from the registry by type), summaries regenerated.
- `specs/tts-module-interface.md`, `specs/benchmark.md`, `benchmarks/latency/README.md` — the attribute, the column, the split.

## Steps

1. Base class and the fifteen modules; the registry test with the mapping.
2. Benchmark: `kind` on every record, in both CSVs, the two-table summary; the test.
3. Migrate the existing records (a one-off script over `runs/*/raw.jsonl` and the result's `raw.jsonl.gz`), regenerate the Mac result.
4. Specs and README.
