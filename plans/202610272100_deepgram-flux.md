# Deepgram Flux TTS (speak v2) alongside Aura-2

**Status:** Done

Implements [specs/modules/deepgram.md](../specs/modules/deepgram.md) ("Two APIs", the `model`, `speed` and `expressivity` fields, "Pending-text backpressure" on Flux), following item 4 of `analysis/api-currency-audit.md` and the rule in [specs/project.md](../specs/project.md) that a module follows the provider's current API and keeps an older one while it is supported and serves its own use case. Flux TTS has been GA on `/v2/speak` since 2026-08-12; Aura-2 on `/v1/speak` stays supported with no sunset announced. The one `deepgram` module drives both, the API picked by the model prefix. Leaves out the spec's deferrals: Flux `Interrupt` / `Configure` and `tag`, a default-model switch, per-API segment thresholds.

## Scope

- `src/tts_engine/modules/deepgram/module.py` — a `flux-` model connects with `speak.v2.connect` and sends text through `send_speak(SpeakV2Speak)`; the finished-segment answer is `SpeechMetadata` on v2 (`Flushed` on v1); v2 `Error` events raise `TTSError`; `expressivity` (Flux only, integer −2..2) and the Flux `speed` range (0.5–1.5, steps of 0.05) validated.
- `tests/modules/test_deepgram.py` — the fake SDK gains `speak.v2` and `deepgram.speak.v2.types`, answers a v2 `Flush` with `Flushed` at once and `SpeechMetadata` after the audio, and closes after `Close` only once every segment is answered (as live); v2 dispatch, completion on `SpeechMetadata`, `Error`, validation rows; the segment tests parametrized over both APIs.
- `tests-e2e/support.py` — a `deepgram-flux` row (`flux-haley-en`), same key.
- `examples/config.deepgram-flux.json` — a complete Flux config next to `config.deepgram.json`.
- `specs/modules/deepgram.md` — status `Implemented` → `Updated` while this plan runs, back to `Implemented` with it; open question 1 rewritten as the decision; the Flux validation record.
- `specs/_index.md`, `specs/testing.md`, `specs/ci.md`, `README.md` — the second API and the second live row.

## Steps

1. Probe the live v2 socket (scratch scripts, not committed) for what the audit left open: the order and meaning of `Flushed` / `SpeechMetadata`, audio before a `Flush`, turn queueing, `Close` without `Flush`, a whitespace turn, a bare `Flush`, many flushes, a 900-character turn, and the handshake bounds of `speed`, `expressivity` and crossed models. Finding that shaped the design: v2's `Flushed` comes when a turn starts, before its audio, so the gate and the end of utterance must count `SpeechMetadata` instead.
2. Module: pick the API from `model` before the lazy import (to import the right message type); validate the new fields; route connect and send; count the API's finished-segment answer in the reader; raise on `Error`.
3. Tests: extend the fake, add the v2 cases, parametrize the segment tests; check that wiring v2 to `Flushed` makes the new tests fail.
4. Live row and example; spec and docs.

## Result

Unit tier 596 cases (12 new), live `-k deepgram` 10/10 on both rows. Engine-level Flux run: a 1534-character `say` across two segments gave 164 s of audio in 115 s, first audio 0.75–0.9 s, cancel surfacing in 0.055 s. Longer single Flux turns (1800 and 3000 characters) were not measured to the end; the module never sends more than 900 characters per turn.
