# MCP server behind an `mcp` extra

**Status:** Done

Implements the settled design in `specs/project.md` ("Key dependencies", "Dependency strategy for transports", "Entry point & plumbing"), `specs/mcp-server.md` ("Installation", "Lifecycle"), and `specs/architecture.md` (the `mcp` extra note, component table, "Public API").

It moves `mcp` and `uvicorn` out of the base dependencies into an `mcp` extra, so `pip install tts-engine` is the engine, tools, config, player, and fixture modules only. `tts-engine-mcp` keeps working with the extra and exits with a `pip install tts-engine[mcp]` hint without it. It deliberately leaves out the HTTP server (`specs/_http-server.md`, still a draft), any change to `mcp.py`'s behaviour, and making `sounddevice` optional.

> **How to work this plan.** Do the parts in order and run the **Checkpoint** commands at the end of each one. The design is decided in the specs above. If a step and a spec disagree, follow the spec and note the discrepancy in your final report. Do not edit `specs/` except for the frontmatter and status lines named in Part C.

### Part B — entry point and guard test

**B1. Rewrite the imports in `src/tts_engine/mcp_server_cli.py`.**

1. Remove the top-level `import uvicorn` and `from tts_engine.mcp import create_server`.
2. Add the hint constant and the root names beside `_LOG_FORMAT`:

   ```python
   _MCP_EXTRA_MODULES = {"mcp", "uvicorn"}
   _MCP_EXTRA_HINT = "tts-engine-mcp requires the mcp extra: pip install tts-engine[mcp]"
   ```

3. In `main`, right after `args = parser.parse_args()` and before `MCPServerConfig.from_json_file`, insert:

   ```python
   # The console script is installed even without the mcp extra, so the MCP
   # stack is imported here: a missing extra becomes an install hint, not a
   # traceback. Any other import error is a real bug and is re-raised.
   try:
       import uvicorn

       from tts_engine.mcp import create_server
   except ModuleNotFoundError as exc:
       if (exc.name or "").split(".")[0] not in _MCP_EXTRA_MODULES:
           raise
       raise SystemExit(_MCP_EXTRA_HINT) from exc
   ```

   Leave the rest of `main` unchanged. `SystemExit` with a string prints it to stderr and exits with status 1. The `name` root check matters: a poisoned or missing `mcp` reports `exc.name` as `"mcp.server"` or `"mcp"`.

4. Update the module docstring to: `"""MCP entry point: parses args, checks the mcp extra, and wires everything together."""`.

**B2. Update the patch targets in `tests/test_mcp_server_cli.py`.** Because `main` now imports at call time, patch the source modules instead of the CLI module's attributes:

- `"tts_engine.mcp_server_cli.create_server"` → `"tts_engine.mcp.create_server"`
- `"tts_engine.mcp_server_cli.uvicorn.run"` → `"uvicorn.run"`

This applies in both `test_main_wires_config_into_server` and `test_log_level_defaults_to_info`. The `TTSEngine` and `logging.basicConfig` patches stay as they are. The assertions do not change.

**B3. Create `tests/test_no_mcp_import.py`**, modelled on `tests/test_no_audio_import.py` (subprocess run, `returncode == 0`, `"OK"` in stdout):

```python
"""Guard: the engine and tools work without the mcp extra installed.

Runs in a subprocess with `mcp` and `uvicorn` made unimportable, so poisoning
`sys.modules` never leaks into the rest of the suite. Proves that
`import tts_engine`, `MCPServerConfig`, and `TTSTools(...).say` on the `tone`
fixture module never import the MCP stack, and that `tts-engine-mcp` exits
with the `pip install tts-engine[mcp]` hint.
"""

import subprocess
import sys
import textwrap

_SCRIPT = textwrap.dedent(
    """
    import asyncio
    import sys

    # As in a base install without the mcp extra.
    for name in ("mcp", "uvicorn"):
        sys.modules[name] = None

    from tts_engine import MCPServerConfig, TTSEngine, TTSTools

    cfg = MCPServerConfig.from_dict({"engine": {"module": {"type": "tone"}}})


    class CaptureSink:
        def __init__(self):
            self.chunks = []

        def feed(self, chunk):
            self.chunks.append(chunk)

        def drain(self):
            pass


    sink = CaptureSink()
    tools = TTSTools(TTSEngine(cfg.engine, sink=sink))
    assert asyncio.run(tools.say("hi")) == "OK"
    assert sink.chunks

    from tts_engine.mcp_server_cli import main

    sys.argv = ["tts-engine-mcp", "--config", "unused.json"]
    try:
        main()
    except SystemExit as exc:
        assert "tts-engine[mcp]" in str(exc.code), exc.code
    else:
        raise AssertionError("main() ran without the mcp extra")

    # Never imported: still the poison sentinels we planted.
    assert sys.modules["mcp"] is None and sys.modules["uvicorn"] is None
    print("OK")
    """
)


def test_engine_and_tools_work_without_mcp_extra():
    result = subprocess.run(
        [sys.executable, "-c", _SCRIPT],
        capture_output=True,
        text=True,
        check=False,
    )
    assert result.returncode == 0, result.stderr
    assert "OK" in result.stdout
```

`unused.json` does not exist, which is on purpose: the extra check runs before the config is read, so the test fails if that order regresses.
