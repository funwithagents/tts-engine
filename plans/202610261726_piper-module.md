# Piper module

**Status:** Done

Implements [specs/modules/piper.md](../specs/modules/piper.md): a local-model `piper` backend on `piper-tts` 1.8 (onnxruntime, espeak-ng compiled in, no torch), behind a `piper` extra with a lazy import. Voices come from `rhasspy/piper-voices` pinned to a commit, with the public-domain `en_US-ljspeech-medium` as the default. Along the way, kokoro's one-sentence-ahead producer moves into a shared `feed_with_lookahead` helper in `base.py`, the updated [tts-module-interface.md](../specs/tts-module-interface.md) and [kokoro.md](../specs/modules/kokoro.md) specify that move, and both modules use the helper. Leaves out the spec's deferrals: Chinese/Japanese/Thai voices, GPU, the other synthesis knobs, alignments.

## Steps

1. **Shared helper.** Move kokoro's `_speak` into `base.py` as `feed_with_lookahead(sentences, synthesize, callback, stop, *, slice_bytes)`, with `synthesize` returning an iterable of PCM chunks. Kokoro calls it with `lambda s: [self._create(s)]` and its 100 ms `_SLICE_BYTES`. Run the kokoro tests unchanged: they must still pass. Add helper tests to `test_tts_module_interface.py`: slicing; one chunk ahead (the second `synthesize` starts while the first chunk is being fed); an error from `synthesize` raised in the caller unchanged; a callback error propagates; `stop` set mid-feed stops callbacks and further `synthesize` calls.

2. **Module** (`modules/piper/module.py`, `__init__.py`).
   - Constants: `_VOICES_REPO = "rhasspy/piper-voices"`, `_VOICES_REVISION = "5041a7a4…"`, `_DEFAULT_VOICE = "en_US-ljspeech-medium"`, speed range, poll/slice settings.
   - Validation before the import, in the spec's order. `_voice_files(key)` → `(repo, onnx_path, revision)`; `_parse_hf` as in kokoro (copied: two small call sites, different error prefixes). A local `model` resolves with `resolve_path`; its config is `Path(str(model) + ".json")`.
   - Lazy imports (`hf_hub_download`, the three Hub error classes, `PiperVoice`, `SynthesisConfig`); local files checked; download `try` (Hub errors → `ConfigError`, others → `TTSError`); load `try` (→ `TTSError`).
   - Post-load: phoneme type (`pinyin` rejected; `phonemize("a")` probe, `ImportError` → `ConfigError`, other → `TTSError`); speaker resolution; `SynthesisConfig` from set fields only; `log.info`.
   - `_synthesize(segment)`: a generator advancing `voice.synthesize` inside a `try` (→ `TTSError`), checking each chunk's rate, yielding `audio_int16_bytes`.
   - Both synthesis methods call `feed_with_lookahead` over `segment_sentences(...)`.

3. **Registry.** Import `PiperModule`, add `"piper": PiperModule`, docstring.

4. **Unit tests** (`tests/modules/test_piper.py`): fakes and coverage as in the spec's "Testing → Unit"; reuse the kokoro test patterns (counting callback for cancellation, event-driven source for the text stream). Within the 5-second budget.

5. **Lazy-import guard and live row**, as for kokoro.

6. **Example and docs** listed in Scope; README states the voice-license table and the GPL note.

7. **Frontmatter**: add `src/tts_engine/modules/piper/__init__.py`, `module.py`, `tests/modules/test_piper.py` to the piper spec, and `tests/modules/test_tts_module_interface.py` stays under the interface spec.

8. **Statuses**: piper spec, kokoro spec, interface spec → `Implemented`; this plan → `Done` (files and indexes).
