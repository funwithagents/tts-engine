| column | meaning |
|---|---|
| TTFA p50 | median time to first audio, `say()` on the short text: the headline |
| TTFA p90 | its tail: 9 runs in 10 answered within this |
| first voice p50 | median predicted first voice, `say()` on the short text: when a player started at the first chunk reaches the first chunk above 500/32767, so a backend opening with silence reads later than its TTFA; a lower bound, accurate to about one chunk |
| TTFA stream p50 | the same short text fed as a token stream (`say_stream()`): the streaming path's own cost or gain |
| TTFA long text p50 | `say()` on the three-sentence text: grows with the text for a backend that does not really stream |
| max gap | median over runs of the longest wait between two audio chunks, three-sentence stream: a stutter only if it outlasts the audio queued in the player, which `continuous p50` accounts for |
| real-time × | audio seconds per wall second of the whole call, three-sentence stream: below 1 the listener waits. `speed_x` in `results.csv` counts only the time after the first chunk |
| continuous p50 | median time to continuous audio, three-sentence stream: the earliest playback start that never runs out, on an ideal queue; above the TTFA a player started at the first chunk stalls |
| CPU peak p50 | median over runs of the CPU use in the call's busiest sampling window, three-sentence stream, percent of one core as top shows it (200 = two cores): what the synthesis grabs at its peak, every thread of the engine's process |
| CPU peak p90 | its tail across runs |
| load s | engine construction: client or socket setup, model load (download included on a first run) |
| first call | TTFA of the very first synthesis after construction (cold connection, kernels); not in the statistics |
| peak MB | peak resident memory of the entry's process after its runs: the model, its runtime, its buffers |
